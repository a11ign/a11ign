**Why the consumer gate's pin is kept, and the generator's dirty-README refusal (#1721) is not tripped.** `generate()` is the generator's own pure function; `main()` bakes `git rev-parse HEAD`, and its refusal exists because an input edit landing in the same commit as that bake makes the baked pin stale on arrival. Here nothing is baked: the committed pin is read back and written back, so a docs re-pin cannot change what check-pin answers, and `consumer-gate-pin.yml` still repairs it when `action.yml` moves. The cost is that the file's pin is not at the base commit; the benefit is that the diff to it is the one comment line and the shape check needs no new rule.
