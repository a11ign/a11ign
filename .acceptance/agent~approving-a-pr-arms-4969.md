`.github/workflows/auto-arm.yml` (this repository) and the same file in a11ign/agent-org (PR there, same branch name) now react to an approving review: an approved draft is marked ready and armed, with no worker turn.

**The design, and why it is not a bare `pull_request_review` job.** `pull_request_review` runs the file as it is on the PR's merge ref, i.e. the BRANCH's copy (`job_workflow_ref` = `...@refs/pull/N/merge`, the shape #4191 measured and #4287 closed), so a minting job on it would either be refused by the policy or, if the policy admitted that ref, let a branch editing the file mint a write token. So the review runs one job, `relay`, that holds `actions: write` and no `id-token`, mints nothing, and dispatches `main`'s copy with the PR number. `arm-approved` is the `workflow_dispatch` half: it runs as `refs/heads/main`, which `auto-arm.sts.yaml` already admits here, so **this repository's policy file is unchanged** (agent-org's gains `workflow_dispatch` in `event_name`, in its PR). `arm-approved` trusts nothing in the dispatch: it re-reads the PR as the minted token and acts only on `reviewDecision == APPROVED`, an open PR against `main`, a head in the repository and no `hold:` label; a held, forked, closed or `CHANGES_REQUESTED` PR is left untouched, **and is not marked ready either**. `sweep` and `stalled` refuse `pull_request_review` and a dispatch that names a PR.
