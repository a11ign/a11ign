**`gate:stability` keeps WHAT varied on a failed canary, and the captures it varied in (#3273, from #3132).** One of ten runs of the same unchanged commit failed on the live `nls.uk/join/` canary with `VARIES transcript counts 11,11,11,11,11` and nothing to say which content differed: the gate kept only the lines containing `VARIES`, not the variant lines `repeat-capture` prints under each, and every canary of every run wrote `capture-1.json` .. `capture-5.json` into the one shared directory, so the failed run's captures were overwritten by the next canary. The gate now reports each `VARIES` line with its variants in its own output and in the result's `detail`, and gives each canary of each run its own directory (`<repeat-captures>/stability/<run>/<canary>`), passed to `repeat-capture` as `--out` and named next to any `UNSTABLE`. What counts as unstable is unchanged, no threshold moved, and the live canary stays; whether it belongs in a gate that blocks a release is the question this evidence is for. The logic lives in `src/gates/stability-canary.mjs`, which does not reach the corpus, so its test runs in the token-less acceptance job.
