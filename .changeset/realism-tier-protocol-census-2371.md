**`build-realism-tier.mjs` prints the capture-protocol census of BOTH halves of `with-realism.jsonl`, and records it in `with-realism.jsonl.source.json` (#2371, from #2215).** Until now no command could say which protocol the training captures were taken under: `lab:job -e job=inventory` groups the whole corpus rather than by declared role, and the only census the lab printed was the calibration one (#2311). One run now prints `real-page {"18":41} n=41` (the `trainingEntries` slice — role from the CORPUS via `realPageFor`, never the stamped role) beside `generated {"21":3742} n=3742` (the `provenance.environment.captureProtocol` stamp on each base record), so a generated-at-21-beside-real-at-18 mix is visible in one line. `n` is printed with the counts, because an empty group is a join that stopped working, not a pass. A census and not a floor, for #2311's reason: which protocol a reading requires belongs to the question asking. The counting lives beside `captureProtocolCensus` in `capture-protocol-census.mjs` (`recordProtocolCensus`, `protocolCensusOfTheMix`, `protocolCensusLines`) so a test can be the Acceptance; the script imports `dataset-paths.mjs`, which CI's acceptance job refuses.
