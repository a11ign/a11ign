**A multi-page run behind a login now REPORTS the logins it performed, states its cost as a minimum, is bounded, and stops on a failed login (#2562).** `--urls` and `--login-flow` already composed and nothing tested it; the shipped code differed from ADR 0038's prose in four places. (1) **The count is a result.** It is counted where a login is sent (each worker capture attempt, re-captures and `--forms` states included, and each rule-layer scan), reported as `logins` in `--json` (`performed`, `workerAttempts`, `ruleLayerScans`, `minimum`) and as a closing `Logins: N performed` roll-up line. **Measured on a fake worker: 3 pages, axe on, one page re-captured once = 7 performed (4 worker attempts + 3 rule-layer scans).** (2) **The pre-run notice is a MINIMUM and says so** ("at least 6 logins"), counted per capture and not per page, so form states are no longer undercounted, and it names the worst case (each capture up to `MAX_CAPTURE_ATTEMPTS` = 3 attempts). It matches the ADR's "at least two logins per capture"; "N captures are N logins" was the floor of a run with no repeats, and "pages x 2" is a floor and never a count. (3) **A lockout guard** refuses BEFORE any lease when the minimum passes `MAX_LOGINS` = 20 = `DEFAULT_MAX_PAGES` x (`MAX_CAPTURE_ATTEMPTS` + 1), the default run's worst case: the default 5-page run (minimum 10) is admitted, 25 pages (minimum 50) is refused, exit 2, naming the constant and the count. **It has no override** (a flag would reach the Action's inputs); the remedies named are a shorter list or `--no-axe`. (4) **A failed login stops the list**: after an authentication fault, later pages are recorded `notAttempted` with the fault named and make no login; a capture timeout still continues. A worker-reported authentication fault now reaches the caller as an `AuthError`, so a single-page run that fails to log in exits 2 (the caller's to fix) rather than 1. Not built: ADR 0038's per-entry `flow:` / `auth: none` list. Not in this change: naming a page that bounces to the login wall mid-run (`auth-session-lost`).
