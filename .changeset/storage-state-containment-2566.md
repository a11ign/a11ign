**The containment for a saved storage state exists before the flag that loads one (ADR 0038, amendment 7, #2566).** Nothing is reachable yet: there is still no `--auth-state`. `scrub.ts` gains `credentialsFromState`, which turns the cookies and `localStorage` a run would load for its pinned origin into values to hide (named by place, `state cookie 3`, never by the file's key or value; a JSON `localStorage` value contributes the strings inside it), and `stateEntriesFor`, the one selection that the later loading is to be built from too. **A value shorter than `MIN_SCRUBBED_LENGTH` is skipped and counted, not refused** (a real state holds many such values), and so is a value that is text the run was itself handed (its URLs or task); `stateScrubNotices` says how many. A new test enumerates every file write under `packages/cli/src/auth/` and in the worker's login against an allowlist of one, and a scratch module that writes a state is caught by the same scan, so the tool provably writes no state file. **Not done:** loading a state, the `auth-state-expired` fault, the worker's wire, the Action's `auth-state:` input, and the real reading on a runner (row item 6).
