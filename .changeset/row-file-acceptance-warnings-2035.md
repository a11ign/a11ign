**`row-file` now WARNS about three ways a row's Acceptance misleads whoever builds it (#2035).** Each prints and files anyway. (1) A `## Region` naming a source file whose import closure needs `corpus` or `history` while the Acceptance runs tests — walked from the Region's files, never the Acceptance command, because at filing time that names a test not written yet and the walk on a missing path returns `[]`, which reads as "needs nothing"; a Region file absent from the checkout is reported as UNREAD, never clean. `token` is deliberately not charged: a test declares `// no-token:` in its own header, and charging it spoke on 79 of 150 rows. (2) A test count quoted in the Acceptance (`132 tests, 0 failed`, `9 passed / 0 failed`, `140/0`, `tests: 46`) with no re-measure sentence anywhere in the body — the spellings are the population's own, read from 70 open and 80 closed rows. (3) An Acceptance "command" that is prose (a paragraph glued to the closing fence, or a section with no fence), asked of `classifyCommand`, naming the one blank line that fixes the glued case. Measured 2026-09-24 at `edf5ec07a` over those 150 rows: closure 47, count 12, malformed 5. `docs/row-filing.md` states the count rule: a quoted count is a reading at a named commit, never a requirement.
