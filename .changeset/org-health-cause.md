**The gate now asks how the org is doing, and wakes `ceo` with the evidence when nothing lands or a red PR ages (#2936, the chairman's "why isn't the agent org self healing ... surely the ceo should be optimising?").** `org-stalled` fires only when no other cause produced an order, so an org busy offering orders and landing nothing was invisible to it, and `pr-checks-failing` woke a PR's owner on the first red and never asked whether that produced a fix. `org-health.mjs` (a leaf, like `repeating-lines.mjs`) reads once per tick the state the gate already holds and offers `ceo` ONE judgment cause, `org-health`, per tripped signal, with the numbers in the prompt: **no PR merged for 3 hours while a green unheld PR or a claimable Ready row exists** (p97.7 of 647 merge gaps over 14 days), **a PR red for 120 minutes with no comment from its owner since** (p95.7 of 462 red-to-next-run ages; a PR with no owner is always unattended), **a Ready row the #2845 counter has seen refused 75 ticks** (structural: 15 for `product-manager` plus one judgment window, because that counter has no history yet), and **the primary checkout off `origin/main` for 60 minutes** (the age `primary-stale` lacked). The thresholds and the table they come from are on the row. Each offer is keyed on the signal and the hour it first tripped, derived from the facts (no file of its own), so it holds rather than re-asking and stops when the signal clears; a refused read is an unknown said on stderr, never a clear. One new REST read, the last merge, counted in `GH_READS`; `pr-checks-failing`'s orders are consumed, not re-derived.

**What it does not do:** run a model turn or a cron, change any existing cause's routing, or measure the fleet and copy-drift signals, the retrospective and the hand-fix count, each its own row.
