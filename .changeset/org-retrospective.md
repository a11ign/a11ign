**`ceo` is now woken once per UTC date with the org's last 24 hours as numbers, and ordered to file CLASS fixes for whatever worsened (#2938).** The chairman's question on 2026-10-01 was *"surely the ceo should be optimising?"*; the record behind it is six rows (#2841, #2842, #2845, #2847, #2853, #2882/#2912), each closing the exact instance the chairman's session found. Nothing woke `ceo` to look at the org, because no cause measured the org's own health. The new `org-retrospective` cause (a JUDGMENT cause, so a drain does not withhold it; sonnet at high effort) is keyed on the UTC date, never the hour.

`org-retro.mjs` (a leaf, no model) computes the numbers once, from the reads the gate already makes: PRs merged and the median open-to-merge; idle minutes while a claimable row existed (ticks whose `ready-row-unclaimed` offer went `UNDELIVERED`, counted at 2 minutes a tick, so a floor); red-PR age (median, max, which PR, from the newest run of each check); `org-stalled` and `claim-stalled` wakes and claims released for a reason other than `merged`; `org-health` offers by signal; tokens per merged PR (`token-audit.mjs`'s own transcript reading, cache reads included); and the chairman's session's hand fixes, which print `ledger absent` until the sibling ledger (#2939) exists. **An unreadable source prints `unknown`, never 0**, and a window with zero merges prints a `STALL` line with the idle minutes beside it.

The gate asks the wake ledger whether today's key was DELIVERED, so an offer the wake could not deliver is offered again next tick and a delivered one is never offered twice in a date. The prompt carries the report, the class-fix instruction (a row whose Acceptance is a test over a population derived from the tree or the API, with a positive control, not over the instance) and the destination, #928; `.agent-org/roles/ceo.md` names the duty in its own section. Run it read-only with `node packages/agent-org/src/org-retro.mjs`.
