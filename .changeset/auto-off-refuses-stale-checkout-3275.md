**The auto-off timer refuses to power anything off when the files it runs differ from `main` (#3275, same class as #3269).** The timer executes `/root/a11y-witness` on the control plane and nothing moves that checkout when `main` moves (its only fast-forward is a side effect of some play), so a safety property merged to `main` was absent from the program that powers boxes off. Under `--apply`, and only when some worker is about to be powered off, `fleet-auto-off.mjs` now fetches `origin/main` (remote-tracking ref only, never the working tree; at most once a minute, stamped in the state file) and compares the working tree against it over the program's own import closure (derived by walking its `import`s, so a new import is covered the day it lands) plus `sleep.yml` and the two unit files. Any difference refuses, and so does any doubt: a failed fetch, an unresolvable `origin/main`, an errored diff or a walk that finds nothing each refuse (`staleCheckoutVerdict`, pure). A refusal is loud: held workers read `keep stale-checkout` in the report, the tick prints `refuse <reason> -- <detail>` and exits 1 so the oneshot unit shows FAILED, and the refusal is recorded in the state file, which `fleet-watch.mjs` now reads from the control host and posts. Report-only runs and ticks with nothing to power off fetch nothing. The unit file and this code reach the control plane only via a play, so the timer carries the check only once `auto-off-schedule.yml` (or any `fleet:*`) has run.
