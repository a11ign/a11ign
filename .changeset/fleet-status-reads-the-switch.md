**`fleet:status` reads the network switch: per worker, `on, MAC on port N`, `off, link up 100 Mb, no MAC`, `off, link down` or `unread` (#3242).** The Netgear GS728TP answers read-only SNMP v2c, so where a worker is and whether it is on is a lookup: `fleet-switch.mjs` walks the forwarding table (BRIDGE-MIB `dot1dTpFdbPort`, Q-BRIDGE `dot1qTpFdbPort` when that is empty), `ifOperStatus` and `ifHighSpeed`, and a pure `switchStates` maps them with each worker's `switch_port:` and `mac:` from the control plane's inventory to one state. A MAC learned on another port is named (`w4's MAC is on port 9, not its own port 17`). The reads are GET and GETNEXT only: `buildRequest` throws on any other PDU tag, a test tries all 256, and the module has no dependencies (the BER encoding is written out). A switch that does not answer prints ONE `switch: unread (…)` line and changes nothing else in the report. The switch's address and community are `A11Y_SWITCH_HOST` / `A11Y_SWITCH_COMMUNITY` or the file `A11Y_SWITCH_FILE` (`host=` and `community=` lines); there is no default, and the community is in no output. **No output says "armed"**: link up at 100 Mb in S5 may mean only that the NIC has power, and nothing has yet shown a known-armed and a known-unarmed box reading differently on this switch.
