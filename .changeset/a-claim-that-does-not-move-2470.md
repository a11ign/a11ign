**A claim that does not move is nudged, then released, and the release KEEPS THE WORK (#2470).** `worker-7` held `#2407` with 215 lines uncommitted, unpushed and no pull request for seven hours while it worked another row; the gate had no cause for a claim going unmoved and the one nudge that worked cost a `ceo` turn spent reading a pane. The new `claim-stalled` cause (an ACTION cause, FINISH: a drain does not withhold it) reads every claimed row: nothing moved for **N = 120 minutes** (a commit on the claimed branch, a push, a row comment by the account that wrote the claim record, a changed file in its worktree; a row with an open pull request belongs to the PR-stage causes) yields ONE nudge; a second reading N minutes later with nothing moved RELEASES it. The session's own status is not an input. N is measured from 297 landed rows (largest ordinary gap 51 minutes, then nothing until 264; p95.6), and the method and every figure are in the pull request.

**The release keeps the work.** `row-claim decline --keep-worktree` leaves the recorded tree in place (it used to remove it first and refuse while dirty); `row-claim claim --adopt=<session>` claims that session's existing tree in place, refused unless the stamp names that session and the tree is on the claim's branch; `decline --answer=<session>` releases to `answer:<session>` instead of `ready`. The respawn adopts the kept tree and is told it is not empty.

**Also released:** a claim whose row has an open `blockedBy` edge and whose holder holds nothing; and a claim whose pull request MERGED while the row stayed open (`Closes: none`), which sets `answer:product-manager` at the merge (read live against the org at the first run: `#2220`/`worker-9` after #2497 and `#2188`/`worker-4` after #2398). A release ends a SPARE's instance and only releases a standing seat's claim, and writes a `spare-cycles` line that neither lifts the #2324 drain nor counts toward #1950's run.

**A delivery a restart killed is re-sent.** A `herdr.service` restart (read through `systemctl --user show ... --timestamp=utc`) voids the ledger lines of deliveries made in the 60 minutes before it whose target then made no move (window measured: p89.9 of 1,352 answered runs), so the gate's order is offered again without spending `MAX_DELIVERIES`, and re-queues authored orders from their retained text; an idle pane whose last line reads `Interrupted · What should Claude do instead?` gets a plain resume prompt. None of these is ever behind a `/clear`, and the no-progress clock starts no earlier than the restart.
