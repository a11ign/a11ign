**The health signal is now "an open PR is not progressing towards merge for 180 minutes, whatever the reason", not only "red" (#2970, the chairman, 2026-10-02).** #2950 sat a draft, `DIRTY`, with no checks for 7.5 hours, and the red-PR signal could not see it: a conflicted draft has no checks and a green PR nobody reviews has no red. `org-health.mjs` gains a seventh signal, `pr-not-progressing`, built on `stallReasonOf` (#2968) so it and the owner's order cannot disagree about which PRs are stuck: it fires for an open PR whose reason is neither `progressing` nor `held-on-purpose` (a `hold:*` or `awaiting-evidence` PR is a decision and is never offered, however old) and that has had no push, review or comment for 180 minutes. `ceo` is offered ONE order naming each PR with its reason, owner (or "NO OWNER") and quiet time, keyed on the set of `number:reason` so it holds while unchanged. **N = 180 minutes is the p94.8 of PR open-to-merge** (670 PRs merged 2026-09-18..10-01: p50/p75/p90/p95/p97.7 = 30 / 59 / 121 / 181 / 432 minutes, measured with `gh pr list --state merged`): a PR quiet for longer than 95% of PRs take to merge entirely is not on its way. A push is not on `pr list`, so a PR whose listed comments, reviews and creation are already over 180 minutes old is asked for its head commit's date (one conditional REST read per such PR, counted in `GH_READS`); a refused read is an unknown, never an age. The gate's own import of `stallReasonOf` was missing and would have thrown at runtime: the process test caught it.

**What it does not do:** a PR the classifier calls `progressing` because its checks never start (pending forever, not conflicted) is still not offered, since the classifier names that as an age question and this row builds on its answer; changing that is a change to `stallReasonOf`.
