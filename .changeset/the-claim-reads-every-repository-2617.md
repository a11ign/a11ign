The claim rules, B4 and `pr-open` no longer assume one repository (child 3b of #69, ADR 0040 decision 2). B4 reads the open pull requests of EVERY code repository `.agent-org/project.json` declares, one `gh pr list` each, and refuses an overlap that lives only in the second, naming the repository and the pull request (`overlaps #7 in owner/repo`); a Region path carries a repository prefix (`nvda-worker:src/x.ts`) and a bare path is the first repository's, so the same file name in two repositories is not a collision. A failed read of any one repository makes B4 INCONCLUSIVE, said aloud with the repository's name, and never "no overlap". The claim's other reads (held rows, `blockedBy`, the Region, own-PR health) take the tracker's repository as an option and default to the first, and `row-claim check --tracker=<key>` reads a row of another tracker; `claim`, `dispatch`, `decline` and `conflict` there are refused before any write, naming the worktree (`wt-<key>-<n>`) and session (`worker-<key>-<n>`) grammar and the label and board rows that own the write. The merge-blocking parser and `pr-open` accept `Closes owner/repo#N` (measured before the change: MALFORMED) and refuse `owner#N`, `owner/#N`, `a/b/c#N`, `owner/repo#` and `#7, owner#8`; a body naming only bare rows is read exactly as before. With one repository declared every rule behaves as it did.
