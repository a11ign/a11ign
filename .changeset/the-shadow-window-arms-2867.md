**The shadow window has a unit pair, a lifecycle and an arming step, and nothing it ships starts it (#2867, child 5f of #69).** `shadow-window.service.in` (`Type=oneshot`, under memory, swap, CPU and task caps, with `AGENT_ORG_HOST` set so the candidate resolves a11ign's project) and `shadow-window.timer.in` (two minutes, the live timer's cadence) install beside the work-tick pair and share none of its text; the work-tick unit renders to the same bytes with and without them. A windowed run (`--window-timer=<unit>`) is dormant until `shadow-window.mjs --arm` creates `<state>/shadow-window-open`, whose content is T0, T-end (T0 plus 1,440 ticks) and the hard stop (T0 plus 52 hours); `--arm` refuses unless the candidate gate's import closure is byte-identical to this checkout's, and prints the candidate and monorepo commits. The window ends itself at 1,440 recorded ticks or at the hard stop, whichever is first: a `stop` row, the timer disabled, the marker removed. A missed tick is a `gap` row (time and cause: `no-tap-file`, `host-restarted`, `runner-refused`) and a refused run a `refused` row; every recorded tick is still counted, and whether a gap resets the count is the close row's rule.
