**You can now test a page behind a login (#2359, ADR 0038).** `--flows <file> --login-flow <name>` (the Action's `flows:` and `login-flow:`) run a form login from a flows file: named steps addressed by accessible name, in a closed vocabulary with no script step, the site's `origin:` pinned, and every secret taken from an environment variable the file names (`from-env:`), never from a flag or an input. The credential never crosses the worker's channel and is replaced with `‹credential›` (in its raw, URL-encoded and base64 forms, with the count disclosed) in everything the run writes or prints; a run that cannot keep it out ends with a named error and writes and prints nothing. An authenticated run presses only what its own files name (`probe-forms` and `probe-navigation` are turned off), says so before it starts, and lists what it pressed. It refuses a remote worker, a value under 8 characters, a non-local judge backend (unless `--send-authenticated-transcript-to-judge-vendor`), and, on GitHub Actions, a repository that is not private. MFA, SSO and CAPTCHA are out of v1: use a dedicated test account without them. See SECURITY.md and docs/github-action.md, "Logging in".
