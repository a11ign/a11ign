**`fleet:deploy`/`fleet:provision` aim a moved worker at its new address only after its SSH host key, recorded under its NAME, verifies strictly (#2832, follow-up to #2803).** A write must not land on a box that merely answers `/health` at an address a stale neighbour entry handed over, so every worker connection now looks its host key up by inventory name (`HostKeyAlias`), and a worker found elsewhere by MAC is checked with a strict, unauthenticated handshake on the control plane before anything is started. One worker whose name has no recorded key, or whose key does not match, refuses the WHOLE run by name (`--allow-offline=<name>` proceeds without it, and that worker is aimed nowhere); the address enters per run as an inventory source of its own, appended last, with the strict flag in the same host block, and the inventory file is never written (#2752 is the durable fix). Each worker's name is seeded only from a key already recorded for its current pin while that pin answers, and the ones it could not seed are reported. The alias lives in `group_vars/a11y_workers.yml` as `ansible_ssh_args`, because ssh takes the first value of an option and `ansible.cfg`'s `accept-new` would beat a `yes` added after it; the control socket's name now carries the worker's name, so a worker aimed at another's address cannot ride its multiplexed master. `fleet-host-identity.test.ts` and `fleet-playbook.test.ts` pin the decision, both fixtures and the wiring.
